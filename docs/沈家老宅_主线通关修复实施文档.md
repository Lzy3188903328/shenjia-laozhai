# 《沈家老宅》主线通关问题修复实施文档

从主菜单开局走到结局是本轮验收标准。2026 年 11 月 21 日的键鼠走查确认，闺房门和扎纸作坊门均能打开，但门洞里的墙体碰撞挡住了角色。测试时临时关闭了这两处挡路的碰撞，随后通过实际操作完成四道谜题并触发双结局。本轮先修门洞，再处理暗格反馈、花厅引导和结局期间的输入。

| 优先级 | 问题 | 交付结果 |
| --- | --- | --- |
| P0 | 闺房、作坊开门后无法通行 | 从天井开门后能步行进入，从房内也能正常返回 |
| P1 | 正厅暗格响了，但抽屉看起来没动 | 按 E 后抽屉拉开，随后出现可拾取的道士手札 |
| P1 | 拿玉佩后缺少去花厅的方向提示 | 任务栏跟随实际线索和拾取状态，玩家能找到下一处地点 |
| P1 | 结局期间仍能打开行囊 | 结局界面独占操作，字幕播放和退出不受普通界面干扰 |

## 一、切分墙体并恢复门洞通行

主要文件为 [WorldBuilder.gd](../scripts/world/WorldBuilder.gd#L60)，涉及 [_build_boudoir()](../scripts/world/WorldBuilder.gd#L466) 和 [_build_workshop()](../scripts/world/WorldBuilder.gd#L512) 的接口位置。

### 复现与原因

- 从天井分别走到东侧的闺房门和西侧的作坊门。正对门按 E，等开门动画结束后持续按 W，角色在门洞外停住。
- `_wall()` 的手动碰撞已经按缺口切分。视觉墙沿整条边每 4 米铺一个模块，仅凭模块中点判断是否跳过。闺房和作坊的对应墙长 8 米，门洞中心在墙段开头后 4 米。模块中点在第 2、6 米，两者都不在门洞里，模块因此完整铺进缺口。GLB 带来的墙体碰撞也随墙模块留在门洞里。
- 实测只关闭门洞内命中的两段导入砖墙碰撞后，玩家就能走进对应房间。门扇的开门逻辑和门框保留在原位置。

### 实现

1. 在 `_wall()` 内用同一组实体区间生成墙网格和碰撞。所有距离沿 `a → b` 的方向计算。把每个缺口换算成 `[c - w / 2, c + w / 2]`，裁剪到 `[0, total]`，排序并合并重叠或相邻区间，再取补集得到墙段。过滤空区间和浮点误差造成的极短片段。
2. 手动碰撞沿实体区间生成，沿用当前的世界碰撞层、墙厚、墙高和父节点规则。每个实体区间内部再按最多 4 米拆分视觉模块。末段按实际长度缩放并放在这段的中点。核对当前墙 GLB 的轴向和边缘包围盒，尤其是有装饰外沿的木墙。
3. 让 `_wall()` 创建的实例由手动碰撞统一负责阻挡。具体做法是在墙实例内停用 GLB 导入生成的碰撞体，范围限定在 `_wall()` 放出的墙模块。保留门扇、门樘、门楣、柱子、柜子和独立装饰的原有碰撞。用 Godot 的「可见碰撞形状」调试视图核对范围。
4. 复核门洞两侧的共用墙。东侧天井与闺房、西侧天井与作坊都使用同一世界门位。切分之后，关门由门扇挡住，开门后保留足够的角色胶囊通行宽度。继续检查现有正厅、祠堂、花厅、暗门和南门路线。

8 米墙的核对样例为 `total = 8`、`c = 4`、`w = 2`。门洞是 `[3, 5]`，实体区间是 `[0, 3]` 和 `[5, 8]`，视觉墙与碰撞都应止于门洞边缘。

### 验收

- 对无缺口、单缺口、多缺口、缺口贴边及缺口顺序不同的输入，验证实体区间和结果拼接。
- 闺房门与作坊门均在关门时阻挡，在从天井按 E 开门后允许角色走进去，再从房内走出来。
- 在门洞中心和门洞两侧分别测碰撞。角色可以通过开口，同时相邻的实墙继续挡住玩家。
- 在可见碰撞调试视图里检查门洞上沿、地面台阶和墙段接缝。确认视觉墙与物理墙均给门扇和角色留出了空间。

## 二、让正厅暗格播放真实开合动画

主要修改 [Drawer.gd](../scripts/interact/Drawer.gd#L18) 和 [WorldBuilder.gd](../scripts/world/WorldBuilder.gd#L319)。

### 复现与原因

解完祠堂牌位后，回到正厅对供桌暗格按 E。会听到拉开音效，道士手札随后出现，但抽屉网格没有移动。运行时确认交互节点上的 `_anim` 为空，供桌模型下面则有 `AnimationPlayer`。现有 `Drawer._ready()` 在交互节点的子树内搜索，无法找到同属供桌的动画播放器。

### 实现

1. 同一个供桌实例中，明确把带有 `drawer_open` 的 `AnimationPlayer` 绑定给 `HallAltarDrawer`。可以在 `_build_main_hall()` 创建暗格交互后传入已找到的播放器，动画的查找范围限定到这个供桌实例。绑定时验证动画存在并指向供桌里的可见抽屉节点。
2. 保留解牌位后开锁的流程。按 E 进入开启状态时立即设置 `_open`，再播放动画和音效。持续按键或重复按 E 时，由现有开启状态防止重复触发。
3. 将内容物生成与开合过程对齐。优先在抽屉到达可拾取位置时生成手札，同时发出 `opened`。使用动画完成信号时，应核对动画名并考虑场景重开或动画被打断，保证内容物至多生成一次。模型缺少动画时沿用定时生成手札的补偿路径，并记录能定位到资产的告警，以免主线被资源异常封死。
4. 用实际玩家视角检查打开后的抽屉、文件位置和准星。确认供桌的静态碰撞给道士手札留出了交互射线空间。其他复用 `Drawer` 的家具仍保留各自的声效、惊吓和一次性奖励。

### 验收

- 牌位未解时按 E，暗格保持锁住，手札数量为零。
- 牌位解开后按 E，用抽屉网格经过的位移或动画播放状态证明它真的拉开。已经触发打开后，持续按 E 只会生成一份手札。
- 用 E 拾取并打开《道士手札》，在线索册中确认它已登记。

## 三、让任务提示指向花厅和朱砂笔

主要修改 [main.gd](../scripts/main.gd#L123) 的 `item_picked` 和 `puzzle_solved`，并核查 [JewelryBoxInteract.gd](../scripts/puzzles/JewelryBoxInteract.gd#L82) 里的任务栏更新。

拿到玉佩后，任务栏目前显示「玉佩已寻回 · 查明此宅真相」。铜镜解开时，任务栏会在朱砂笔被拾取前写成「朱砂笔已到手」。按实际状态给出目的地提示，保留谜题需要玩家自行推理的部分。

| 触发与条件 | 建议任务栏文案 |
| --- | --- |
| 八卦锁已解开，玉佩仍在妆奁盒旁 | 妆奁已开启 · 取出玉佩 |
| 刚拾取玉佩，花厅铜镜尚未解开 | 玉佩已寻回 · 去正厅东侧的花厅查看铜镜 |
| 铜镜已经解开，朱砂笔未拾取 | 屏风后有暗龛 · 取出朱砂笔 |
| 朱砂笔已拾取，仪式尚未完成 | 朱砂笔已到手 · 去扎纸作坊 |
| 仪式完成 | 书架后有风 · 探寻密道 |
| 追逐已开始 | 显示现有终局目标 |

1. 让 `main.gd` 通过已有的 `GameState` 解谜标记和道具状态更新这段任务栏。将妆奁开盒、拾玉、解镜、拾笔放在同一套优先级下，避免 `JewelryBoxInteract.gd` 和拾取信号互相覆盖。
2. 先处理更靠后的进度。玩家先去花厅或先拿朱砂笔时，随后拾玉仍显示作坊或密室阶段的目标。剧情闪回、拾取提示、婚书组合回忆仍由原信号触发。
3. 对异步惊吓后的任务栏更新也检查当前进度。例如解牌位启动灯灭演出后，延迟返回的回调应依据当时的任务状态显示文案。密室或追逐已经开始时，任务栏继续显示对应阶段。
4. 可以在花厅初次进入时补一条场景内提示「烛光落在第一面铜镜边上，沿光路看看」，供玩家辨认谜题起点。

验收时至少测两条顺序。一条从妆奁拾玉后去花厅，应该先收到花厅目的地，再收到朱砂笔拾取提示。另一条先解镜或先拾笔，再去闺房拾玉，任务栏应保留当前较靠后的有效任务。保留将玉佩带回供桌的真结局条件。

## 四、让结局演出独占输入

主要修改 [main.gd](../scripts/main.gd#L134)、[Endings.gd](../scripts/world/Endings.gd#L36)，并核对 [Player.gd](../scripts/player/Player.gd#L257)、[EscapeDoor.gd](../scripts/world/EscapeDoor.gd#L14) 和 [JadeChoice.gd](../scripts/world/JadeChoice.gd#L19) 的入口。

走到南门触发《长夜》后，按 Tab 会打开行囊并暂停场景，按 Esc 关闭行囊后又能继续。结局从开始播放到出现退出提示期间，应独占普通游戏输入。

1. 把 `GameState.ending_reached` 接到主场景的专用结局处理方法。使用场景级结局状态作一次性保护，先进入结局状态，再归拢任何已出现的普通 UI，最后调用 `endings_ui.play_ending(ending_id)`。将鼠标释放放在普通 UI 收拢之后，确保最终鼠标状态由结局决定。
2. 复用 `player.lock_input(true)`，并清掉水平速度，防止角色在画面淡出时继续滑行。主场景的全局快捷键在结局状态直接返回。正常探索时 Tab、J 和 Esc 的操作照常。
3. 让结局界面保留自己的输入处理。字幕播放中的 Esc 不打开暂停菜单。退出提示出现后，Esc 才执行原有退出逻辑，并由结局界面消费这次按键。
4. 依照 `ending_done` 对出口和供桌交互做一次性保护，避免连续按 E 触发两次。保留南门与归还玉佩各自的触发条件和字幕。也检查延迟的死亡重生、淡入淡出回调，结局已启动时停止接管角色位置、追逐状态和鼠标模式。

| 操作时机 | 预期行为 |
| --- | --- |
| 正常游玩时按 Tab、J、Esc | 行囊、线索册、暂停功能按原逻辑工作 |
| 结局刚开始按 Tab、J、E、G，或持续按 W | 普通界面和交互不启动，角色不继续移动，结局推进 |
| 播放中按 Esc | 字幕继续按现有节奏播放 |
| 退出提示出现后按 Esc | 通过结局界面退出一次 |
| 到达玉佩台或南门后连按 E | 对应结局只触发一次 |

## 五、回归测试和交付

### 执行顺序

1. 先修墙体切分并补齐闺房与作坊的双向穿行测试。
2. 验证暗格动画和手札拾取，再处理任务提示及结局输入。
3. 运行已有测试，并用当前正式模型完成独立的两局主线走查。一局去天井归还玉佩，一局从南门逃离。

### 测试要求

- 把门洞、暗格和结局输入用例补进 `tests/input_regression.gd` 或 `tests/windowed_check.gd`。专项用例可以设置站位和剧情前置条件；被测动作仍由 E、WASD 或对应快捷键触发。
- 主线走查从主菜单开始，合信后走入正厅和祠堂，排牌位并拾取手札，走进闺房解八卦锁，在花厅转铜镜并取得朱砂笔，走进作坊点睛、上香、敲铃，进密室读血书，最后在一局中还玉、另一局走南门。全流程通过正常输入推进。
- 记录闺房、作坊开门前后的实际可达性，抽屉动画的开始和奖励出现，以及两个结局的最终字幕和退出提示。全流程录像或关键阶段日志至少保留一种。
- 检查开门、解谜、结局等新增断言确实执行。交付时记录每组测试的通过数和失败数。

从项目根目录按现有场景入口运行。将 `Godot` 换成本机的 Godot 4.7 可执行文件。

~~~sh
Godot --headless --path . res://tests/asset_audit.tscn
Godot --headless --path . res://tests/smoke.tscn
Godot --headless --path . res://tests/playthrough.tscn
Godot --headless --path . res://tests/input_regression.tscn
Godot --path . res://tests/windowed_check.tscn
~~~

完成条件是**闺房和作坊的门能从两侧通行，暗格动画与拾取反馈一致，任务栏能把玩家引向下一处地点，两条结局都能从正常开局触发并播完**。以当前正式模型和真实键鼠路径复验。
